## Problem

Browsers expect HTTP/2 over TLS, and it removes head-of-line blocking at the connection level for asset-heavy pages.

## Proposal

HTTP/2 over the runtime the spike chose, using `h2` if the spike showed it works there, otherwise our own framing. Stream concurrency and flow-control windows are bounded. It is protected against rapid reset (CVE-2023-44487).

## Budget impact

`no-alloc` on the static path, measured over HTTP/2 as well.

## Acceptance criteria

- [ ] h2spec passes in full.
- [ ] A rapid-reset flood test leaves the server responsive to other connections.
- [ ] h2load numbers against HTTP/1.1 are recorded in `bench/results`.
